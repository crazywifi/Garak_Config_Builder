Step 3: REST API Configuration

✓ REST Configuration Not Needed

You selected a built-in generator. Skip this step unless you want to test a custom REST API.

🌐 Test Your Own LLM Web App / API

Paste a raw HTTP request and, optionally, a matching raw HTTP response from Burp Suite or browser DevTools. Mark the request field where Garak should inject prompts and the response field Garak should read back as the model output.

⚠️ Select the INPUT Field

Click on the field where Garak should inject test prompts. Usually called "message", "prompt", "content", "query", or similar.

Replace the actual user message with $INPUT - Garak will inject test prompts there.

⚠️ Select the OUTPUT Field

Choose the field that contains the actual model reply. Garak will read that field back during detection. If the endpoint returns plain text instead of JSON, set the response format to plain text below.

Maps to plugins.generators.rest.RestGenerator.name. If omitted, Garak uses the URI.

Maps to key_env_var. Use $KEY inside headers or request templates.

Use req_template_json_object semantics for valid JSON bodies and req_template for raw text or multipart payloads. The builder chooses the correct Garak field automatically.

Common browser-only headers are filtered out automatically. Header values can also use $INPUT and $KEY.

Maps to response_json. Use JSON only if the endpoint really returns JSON.

Examples: text, answer, or $.choices[0].message.content. Leave empty for plain-text responses.

🔌 Advanced Options

Maps to proxies.http and proxies.https.

Garak default is 20 seconds for REST if you do not override it.

Maps to ratelimit_codes. These responses are retried by Garak.

Maps to skip_codes. These responses are treated as non-generations and skipped.

Maps to verify_ssl as true, false, or a CA bundle path.

Merged into plugins.generators.rest.RestGenerator for documented REST-generator settings not surfaced above.

Step 6: Attacker & Judge LLM Configuration

🤖 Advanced: Attacker & Judge LLMs

Some probes (TAP, PAIR, GOAT, atkgen) use an attacker LLM to generate jailbreaks. Garak judge detectors use an OpenAI-compatible judge model such as OpenAI, Azure OpenAI, NIM, or Groq. This section writes probe and detector config blocks, not just labels.

⚠️ Attacker LLM Required

You selected probes that require an attacker LLM (TAP, PAIR, GOAT, or atkgen). Configure below.

⚔️ Attacker / Red Team LLM (for TAP, GOAT, atkgen)

When set, this writes attack_model_config.uri. Use this for LM Studio or another custom OpenAI-compatible endpoint instead of Garak's default local URI.

Merged into attack_model_config or red-team model config for documented attacker-generator settings.

For LM Studio or any other OpenAI-compatible local server, use openai.OpenAICompatible. Garak's documented default URI for that generator family is a local OpenAI-style endpoint.

⚖️ Judge / Evaluator LLM (for judge.* detectors, TAP evaluator)

When set, this writes detector_model_config.uri and TAP/PAIR evaluator_model_config.uri. Use this for LM Studio or another custom OpenAI-compatible endpoint.

Merged into detector_model_config and TAP/PAIR evaluator_model_config.

LM Studio works here through Garak's OpenAICompatible generator family, which is explicitly documented as the compatibility base used by judge-capable backends.

What are Buffs?

Buffs transform prompts before sending to the AI. For example: translate to other languages, paraphrase, encode in Base64, or lowercase. This tests if the AI's defenses work against transformed inputs.

🖥️ Using LM Studio / OpenAI-Compatible Local Server?

You must set a dummy API key before running Garak. LM Studio doesn't require a real key, but Garak expects one.

CMD (Command Prompt):

set OPENAICOMPATIBLE_API_KEY=lm-studio

PowerShell:

$env:OPENAICOMPATIBLE_API_KEY = "lm-studio"

Run this command in the same terminal window before running garak --config. Or set it permanently in Windows Environment Variables.
